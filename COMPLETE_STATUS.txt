================================================================================
DATABASE WORKFLOW STATES
================================================================================

ClinicalCase Status Transitions:

1. CREATED
   └─→ Initial state after case creation
       Fields: case_id, patient_id, status
       Next: SCANNING

2. SCANNING
   └─→ Image/data acquisition phase
       Fields: scan_data (JSONB)
       Next: ANALYZED

3. ANALYZED
   └─→ Biomechanical analysis complete
       Fields: biomechanical_profile (JSONB), analysis_confidence
       Next: SUGGESTIONS_GENERATED

4. SUGGESTIONS_GENERATED
   └─→ AI recommendations created
       Fields: suggestions (JSONB), primary_condition
       Next: SUGGESTIONS_REVIEWED

5. SUGGESTIONS_REVIEWED
   └─→ Clinician review complete
       Fields: clinician_notes (via CaseNotes)
       Next: ADJUSTMENTS_CONFIRMED

6. ADJUSTMENTS_CONFIRMED
   └─→ Parameters finalized
       Fields: insole_parameters (JSONB), modified_by_clinician
       History: AdjustmentHistory record created
       Next: GEOMETRY_GENERATED

7. GEOMETRY_GENERATED
   └─→ 3D model created
       Fields: geometry_file_path, geometry_notes
       Next: READY_FOR_EXPORT

8. READY_FOR_EXPORT
   └─→ STL file prepared
       Fields: stl_file_path
       Next: EXPORTED

9. EXPORTED
   └─→ STL exported successfully
       Fields: export_timestamp
       Next: PRINTED

10. PRINTED
    └─→ Physical printing complete
        Fields: print_notes
        Next: DELIVERED

11. DELIVERED
    └─→ To patient
        Fields: delivery_date
        Next: FEEDBACK_COLLECTED

12. FEEDBACK_COLLECTED
    └─→ Post-use feedback received
        Fields: clinical_feedback, patient_feedback, quality_score
        Next: ARCHIVED

13. ARCHIVED
    └─→ Historical record
        Fields: archive_timestamp
        End state

Each transition:
- Updates status in database
- May create related records (CaseNotes, AdjustmentHistory)
- Triggers API responses
- Maintains full audit trail
